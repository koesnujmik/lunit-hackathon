# Lunit Hackathon

Two-phase Lunit L2 submission harness for the Lunit Hackathon HealthBench track.

## Submission Branch

```text
lunit/hackathon-submission
```

## Notes

- Final answers must be generated by Lunit L2.
- Do not commit API keys, local `.env` files, or dashboard secrets.
- The evaluation environment is isolated, so runtime dependencies must be declared explicitly.

## Quick Start

Create a local environment file from the example:

```bash
cp .env.example .env
```

Then edit `.env` and set your team API key:

```bash
export LUNIT_FM_API_KEY="lunit_..."
export LUNIT_FM_API_URL="https://model.hackathon.lunit.io"
export LUNIT_FM_MODEL="Lunit/L2-preview"
export LUNIT_MCP_URL="https://mcp.hackathon.lunit.io/mcp"
```

## Harness Architecture

The driver follows L2's recommended split instead of treating it as a one-shot chat model:

```text
conversation
    -> generation L2
       -> direct final answer, or
       -> retrieve_relevant_content(self-contained query)
          -> retrieval L2
             -> bounded Lunit MCP tool loop
             -> finalize_retrieval(cite_uid selection)
          -> materialized evidence
       -> generation L2 final answer with numbered citations
```

- Generation receives only `retrieve_relevant_content`.
- Retrieval receives the Lunit MCP tools plus the local `finalize_retrieval` function.
- The same `Lunit/L2-preview` model is called with separate system prompts for each phase.
- Common questions stay on the one-call fast path. Source-dependent questions use retrieval.
- Retrieval failures are returned to generation as `no_evidence`, so the final response is still
  generated by L2.

Runtime controls:

```bash
export LUNIT_ENABLE_RETRIEVAL=true
export LUNIT_ROUTING_MODE=hybrid
export LUNIT_MAX_RETRIEVAL_TOOL_CALLS=6
export LUNIT_MAX_TOOL_RESULT_CHARS=12000
export LUNIT_MAX_EVIDENCE_CHARS=24000
```

`hybrid` forces retrieval for explicit source requests, allows it for recognized source families,
and keeps ordinary medical questions on the direct path. Set `LUNIT_ROUTING_MODE=model` to let L2
decide on every question during routing experiments.

Run a single L2 answer:

```bash
source .env
PYTHONPATH=src python -m lunit_hackathon.run_once "환자가 갑자기 흉통과 호흡곤란을 호소합니다. 어떻게 안내해야 하나요?"
```

Run a basic 3-turn Patient Simulator conversation:

```bash
source .env
PYTHONPATH=src python -m lunit_hackathon.run_simulator --turns 3
```

Simulator logs are written under `logs/` and are ignored by git.

Run the dependency-free unit tests:

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

## Submission Service

The submitted container serves an OpenAI-compatible API on port `8000`:

- `GET /v1/models`
- `POST /v1/chat/completions`

Run locally without Docker:

```bash
source .env
PYTHONPATH=src python -m lunit_hackathon.server
```

Build and run the submission container:

```bash
docker build -t lunit-hackathon:local .
docker run --rm --env-file .env -p 8000:8000 lunit-hackathon:local
```

Smoke test:

```bash
curl http://localhost:8000/v1/models
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"lunit-basic-driver","messages":[{"role":"user","content":"기침과 열이 있습니다. 어떻게 해야 하나요?"}]}'
```

Submit the full 40-character SHA from the submission branch:

```bash
git rev-parse HEAD
```
